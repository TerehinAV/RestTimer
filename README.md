# RestTimer

Мобильный вебапп таймеров отдыха для спорта. Работает как Telegram Mini App и как обычное веб-приложение, полностью серверлес — хостится на GitHub Pages. Версия **0.1.24 beta**. Автор: [TerehinAV](https://github.com/TerehinAV).

**Терминология:** _серия_ — настраиваемая последовательность таймеров отдыха (например «Жим лёжа: 1:30 × 8, +15с»); _таймер_ — один интервал отдыха внутри серии; _сессия_ — конкретный запуск серии.

## Возможности

- **Серии таймеров отдыха**: первый таймер (5 с – 30 мин), количество (1–30), прирост (+0…+60 с). Живой превью суммы серии в мастере.
- **Мастер настройки** — шаги с iOS-барабанами (scroll-snap, без слайдеров), 6 стандартных пресетов времени + до 6 пользовательских; отдельно до 6 пользовательских комбинаций «Количество таймеров + Прибавлять по» (например `4 +15`, `6 +20`). Выбранный пользовательский пресет можно удалить.
- **Параллельные сессии** — сценарий тренера: несколько серий запущены одновременно, переключение чипами/свайпом, голос только у серии в фокусе, у фоновых — звуковой сигнал и бейдж «завершилась без тебя».
- **Экран сессии**: активный таймер — огромные цифры по центру, счётчик подходов, таймер превышения отдыха (до ×5 завершённого таймера), завершённые — фейдом сверху, очередь снизу; тап = старт/пауза/продолжение; ghost-кнопки «Заново», «Предыдущий» и «Пропустить».
- **Голос и звук**: пре-генерированная нейро-озвучка (ru/en) — старт отдыха, метки «15 / 10 / 5 4 3 2 1», конец отдыха, завершение серии; синтезированные бипы.
- **Шаринг конфигурации**: диплинк `?cfg=…` (LZString + base64url), QR-код, отправка в чат через `t.me/share/url` (в Telegram) или Web Share API (в браузере).
- **Импорт**: по ссылке из чата, сканирование QR камерой, распознавание QR из изображения галереи; предпросмотр с выбором серий → «Добавить выбранные» или «Заменить весь реестр».
- **Реестр**: карточки серий с суммой, **теги** (например, имена подопечных) с фильтрацией одним тапом, сортировка long-press drag, удаление свайпом с undo. Живой расчёт вместимости экспорта — на экране «Поделиться».
- **Тёмная/светлая тема** в стиле iOS Clock, локализация ru/en (авто + ручной оверрайд), PWA с офлайн-кешем (код и аудио).

## Озвучка — текущий статус

В репозитории лежат **23 из 24** готовых файлов (частота 24 кГц, моно, 48 кбит/с — записаны вручную). Отсутствуют:

| Файл | Язык | Фраза |
|---|---|---|
| `public/audio/en/end.mp3` | en | "Rest complete" |

Отсутствующие файлы не ломают приложение — метка просто не прозвучит.

### Точечная догенерация (OpenAI TTS)

```bash
export OPENAI_API_KEY=sk-...
pnpm generate:voice -- --only end:en
```

Формат `--only`: список `ключ:язык` через запятую; можно фильтровать только по ключу (`--only n10`) или только по языку (`--only en`). Полный список фраз — в `scripts/manifest.phrases.json`.

**Внимание:** полный запуск `pnpm generate:voice` (без `--only`) перегенерирует **все 24 файла** и перезапишет записанные вручную (файла хэшей `.hashes.json` нет, т.к. текущие файлы записаны не скриптом). Полный прогон имеет смысл, только если хочешь заменить всю озвучку на голос OpenAI.

### Конвертация через ffmpeg

Один файл (любой входной формат: wav, m4a, ogg, flac…) → итоговый формат приложения. Команда переводит в моно-MP3 48 кбит/с и обрезает тишину в начале и конце записи:

```bash
ffmpeg -i "вход.wav" \
  -af "silenceremove=start_periods=1:start_threshold=-45dB,areverse,silenceremove=start_periods=1:start_threshold=-45dB,areverse" \
  -vn -ac 1 -ar 44100 -codec:a libmp3lame -b:a 48k \
  "public/audio/ru/start.mp3"
```

Пакетная конвертация папки, если файлы уже названы по ключам (`start.wav`, `n15.wav`, …):

```bash
mkdir -p public/audio/ru public/audio/en
for f in исходники/ru/*; do
  ffmpeg -i "$f" \
    -af "silenceremove=start_periods=1:start_threshold=-45dB,areverse,silenceremove=start_periods=1:start_threshold=-45dB,areverse" \
    -vn -ac 1 -ar 44100 -codec:a libmp3lame -b:a 48k \
    "public/audio/ru/$(basename "${f%.*}").mp3"
done
```

Что делают параметры: `-af …` — удаляет тишину с обоих концов (можно убрать, если фразы уже нарезаны); `-vn` — отбрасывает обложки/видео-дорожки; `-ac 1` — моно; `-ar 44100` — частота; `-b:a 48k` — битрейт 48 кбит/с.

Примечания: файл `public/audio/.hashes.json` нужен только скрипту генерации — при ручной установке он не требуется. Если позже запустить `pnpm generate:voice`, скрипт не найдёт своих хэшей и перезапишет ручные файлы — учтите это. Отсутствующие файлы просто не проигрываются (ошибки не будет).

## Публикация на GitHub Pages

1. Запушьте репозиторий на GitHub (ветка `main`).
2. **Settings → Pages → Source: GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` срабатывает на каждый push в `main`: тесты → сборка → деплой `dist/`.
4. Приложение появится на `https://terehinav.github.io/RestTimer/`.

При переименовании репозитория поменяйте `BASE_PATH` в `vite.config.ts` на новый под-путь (единственная константа).

## Настройка Telegram-бота (Mini App, без сервера)

1. В [@BotFather](https://t.me/BotFather): `/newbot` → выберите имя и username.
2. `/setmenubutton` → выберите бота → **Web App** → укажите URL `https://terehinav.github.io/RestTimer/` → название `RestTimer`.
3. Готово: у бота появится кнопка-меню, открывающая приложение как Mini App (тема/хаптика/локаль Telegram подхватятся автоматически).
4. Диплинк для Mini App: `https://t.me/<bot_username>?startapp=<cfg>` (пейлоад ≤ 512 символов, приложение читает `start_param` / `tgWebAppStartParam` при запуске).

Бот не требует сервера и кода: всё взаимодействие (шаринг в чат) идёт через `t.me/share/url`, а состояние — в ссылке/QR.

  theme/     tokens.css (палитра iOS Clock), apply.ts

Принципы движка: абсолютный дедлайн (`endAt = now + remaining`), тики только для UI/событий; после фонового простоя — пересчёт, просроченные события срабатывают однократно, «прошлые» голосовые метки пропускаются (нет очереди из 15/10/5 подряд).

## Фоновая музыка, гарнитура и lock screen

- Режимы озвучки: опция «Озвучка в беззвучном режиме» **вкл** — фраза идёт с сессией `playback`: слышна даже при беззвучном рычажке, но фоновая музыка на время фразы прерывается и **iOS не возвращает её автоматически** после (поведение как у YouTube в Safari; восстановление из веба недоступно). Опция **выкл** — фраза идёт с сессией `transient-solo` (с фолбэком на `transient`): по спецификации W3C такой звук приглушает другой и должен вернуть его после окончания; фактическое поведение зависит от версии WebKit. Диагностика пишет применённый тип в `audioSession.type`.
- **Safari**: `transient` работает как задумано — музыка приглушается на фразу и возвращается (подтверждено тестами).
- **Telegram Mini App на iOS**: аудиосессией владеет приложение Telegram (общая с голосовыми сообщениями, non-mixable). Внешняя музыка (Apple Music и др.) после фразы **не возобновляется**; музыка **встроенного плеера Telegram** заглушается ещё сильнее — она делит одну аудиосессию процесса с webview, уступает фразе и не возвращается. Поведение одинаково при запуске через «Open» из списка чатов и через main-button. Страница в webview не может управлять ни сессией, ни внутренним плеером хост-приложения — это ограничение платформы; для тренировок с любой фоновой музыкой используй PWA/Safari.
- Управление таймером кнопками Bluetooth-гарнитуры скрыто и отключено флагом `HEADSET_CONTROL_ENABLED`: на реальных iOS-устройствах оно ненадёжно, а в Telegram iOS `navigator.mediaSession` отключён внутри WKWebView.
- Если перед блокировкой экрана активным было другое приложение, iOS может заморозить WebContent. Запустить новую фразу из приостановленного PWA/Mini App надёжно невозможно без постоянно активной аудиосессии (которая конфликтует с музыкой).
- Живой countdown на lock screen невозможен в чистом PWA/Telegram Mini App. Для него нужен нативный iOS-компаньон с ActivityKit/Live Activities. Web Push может дать только отдельное уведомление и требует backend — это не обновляемый таймер.

## Известные ограничения платформ

- **iOS, беззвучный режим**: рычажок «звонок/беззвучный» заглушает веб-аудио из динамиков (и голос, и бипы). В наушниках звук может идти даже в беззвучном режиме — это поведение маршрутизации iOS, а не разделение в приложении. Для озвучки из динамиков переключите телефон в режим звонка и поднимите медиа-громкость.
- **iOS, заблокированный экран**: звук из браузера не гарантирован системой. При возврате на вкладку просроченные события отыграют однократно. Держите экран включённым (Wake Lock запрашивается, где поддерживается).
- **Wake Lock в Telegram webview** не гарантирован — feature-detect, не критичный путь.
- Лимит пейлоада Mini App-диплинка — 512 символов; полные реестры передавайте обычной ссылкой или QR (бюджет ~1200 символов, live-подсветка в реестре и на экране шара).

## Скрытая диагностика

На экране настроек — **5 тапов по строке версии** внизу (в течение 3 секунд) → base64-отчёт копируется в буфер обмена (в webview, где буфер недоступен, отчёт показывается текстом для ручного копирования). Отчёт содержит: окружение (UA, экран, safe-area, service worker, localStorage), полный срез Telegram WebApp SDK (platform, colorScheme, инсеты, viewport), факт наличия `navigator.mediaSession` и какие actions зарегистрировались, счётчики использования функций за сессию (экраны, запуски серий, голосовые метки, шаринг, сканирования), ошибки страницы и отказы воспроизведения аудио. Раскодировать: `echo '<base64>' | base64 -d | jq`.

## FAQ

**Как перенести серии на новое устройство?** Экран «Поделиться» → выбрать все → QR или ссылка → открыть на другом устройстве → «Заменить весь реестр».

**Тренер → подопечный?** Тренер шарит серию (ссылка/QR), подопечный открывает и добавляет её себе, запускает независимо.

**Работает офлайн?** Да, после первого открытия (PWA precache кода и аудио). Установите на главный экран через меню браузера «Добавить на гл. экран».
